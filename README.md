Archon 65
=========

A MEGA65 remake of **Archon** (Free Fall Associates / Electronic Arts, 1983), the chess-like
battle of Light against Dark in which every capture is fought out in an action arena. It runs
in 320x200 with 256 colours.

Everything the game is built from is in `src/assets/`: PNG sprite sheets and asm tables, all
editable.

Build
-----

Run `build.bat`. It:

1. runs `tools/build_assets.py`. It reads the PNG sheets in `src/assets/sprites/`, makes the
   256-colour palette and the packed sprite files in `target/assets/`, and generates
   `src/gen/` (palette, colour names, sprite ids and boxes, the asset manifest);
2. assembles `src/main.asm` with 64tass, including `src/assets/*.asm` (font, tables,
   messages, sound) and `src/gen/*.asm`;
3. writes `target/archon65.d81` (the game, `AUTOBOOT.C65` and the assets) with c1541.

The build needs Python 3 with Pillow. To change graphics, text, rules or sounds, edit
`src/assets/` (see `src/assets/README.md`) and rebuild.

Run
---

`run.bat` builds the game and starts Xemu with `-autoload`. On a real MEGA65, mount the D81
and it starts from `AUTOBOOT.C65`. Loading takes a few seconds: about 160 KB of packed
graphics go into attic RAM.

Controls
--------

| Where | Control |
|---|---|
| Title | **F3**: two players, computer plays Light, or computer plays Dark. **F5**: who moves first. **F7** or fire: start. After 20 s without a key, the computer plays itself (demo); any key or joystick press returns to the title. |
| Board | Light uses joystick port 1, Dark port 2. Against the computer, either port works. The keyboard (cursor keys or W A S D, with SPACE or RETURN as fire) also plays Light, or plays the human side against the computer. |
| Moving | Move the frame onto your icon and press fire to pick it up. Steer it (ground movers step and can backtrack; fliers and teleporters go anywhere in range) and press fire to drop it. Dropping on an enemy starts a fight. |
| Spells | Pick up your Wizard or Sorceress and drop it back on its own square. Up/down choose a spell, fire casts it, Cease Conjuring cancels. |
| Arena | Move with the stick. Hold fire and point the stick to attack in that direction; you can't walk while fire is held. Phoenix and Banshee attack without aiming. |
| Any time | **RUN/STOP** pauses a fight against the computer. **Q** abandons the game. |

Architecture
------------

The game logic is plain sequential code that calls `frame` whenever it waits. `frame` draws the
current scene into the back buffer, flips it at the next vertical blank, and reads the controls.

| File | Contents |
|---|---|
| `src/main.asm` | Boot, `frame`, top level (title, game, result) |
| `src/game.asm` | Rules: turn loop, luminance cycle, healing, win checks, combat results |
| `src/board.asm` | Drawing the strategy screen, the zoom into the arena |
| `src/player.asm` | Controls, the human player's moves |
| `src/spells.asm` | The spell menu, the seven spells' targets and effects |
| `src/combat.asm` | The arena: fighters, missiles, melee, Phoenix fire, Banshee wail, barriers, lifelines |
| `src/ai.asm` | The computer: board planner (spells, then move scoring) and arena AI |
| `src/sound.asm` | Sound effect streams (SID 1, a voice per side) and music (SID 2) |
| `src/title.asm` | Title, options, demo, game over |
| `src/fx.asm` | Spell effects: hardware-sprite animations over the board, flights, the Shift Time pulse |
| `src/gfx.asm` | Screen and palette setup |
| `src/boot.asm` | Loads the packed assets into attic |
| `src/assets/` | The game's assets: sprite PNGs, font, tables, messages, sound (edit these) |
| `src/gen/` | Generated by `tools/build_assets.py` at every build (not in git) |

Library modules used (`src/lib/`): system, dma, loader, unpack, input, keyboard, video_fcm,
blit, sprite_touch, draw, hwsprite, palette, fcm_text, fcm_cache, math.

**Spell effects** (`src/fx.asm`) are VIC-IV hardware sprites over the framebuffer, so they
cost no drawing.
* An effect frame is 32 × 32: two 16-colour sprites side by side, 32 rows tall.
* Each effect has its own 15 colours in the sprites' palette bank (bank 1; the screen
  uses its own bank).
* Up to four play at once, on sprite pairs. They can fly along an arc (Exchange).
* The spell routines shared by the player and the computer start them, so both get them:

| Spell | Effect |
|---|---|
| Teleport | Sparks spiral up and the icon is gone; at the landing they spiral down (any teleport landing, also the mages' moves) |
| Heal | A ring of light at the icon's feet, golden motes rising |
| Shift Time | The board dims and comes back (a palette pulse) |
| Exchange | Both icons leave as orbs that fly past each other and land |
| Summon Elemental | A burst in the elemental's colours where it appears |
| Revive | A beam of light comes down; the icon appears in it |
| Imprison | Links fly in from both sides and lock into the chains |

The frames are in `src/assets/effects/` (editable). The build quantises each effect to its
15 colours.

At build time `tools/build_assets.py` quantises every colour into one 256-colour palette:

| Entries | Use |
|---|---|
| 0-39 | Fixed: UI and luminance colours |
| 40-46 | The logo |
| 80-255 | The art |

The pieces on the board are each type's standing combat frame. Dark faces left.

**Memory**

| Area | Use |
|---|---|
| `$2001`-`~$A000` | Program |
| `$0800`, `$1000` | Screen RAMs (`video_fcm`) |
| `$20000`-`$3FFFF` | Sprites, 512 bytes each: ids 0-107 static (icons, barriers, effects, logo); 192-223 and 224-255 the two fighters' sets |
| `$40000`, `$50000` | Framebuffers. At boot they are also the unpack and staging buffers |
| `$12000`-`~$1E400` | Spell effect frames (16-colour sprites, 512 bytes a frame), copied from attic after boot |
| `$8000000` | Static sprite sheet (copied to `$20000` after boot) |
| `$8020000` | 20 combat sets (one per type, 16 KB each), DMAed in for each fight |
| `$8070000` | Spell effect frames |
| `$8100000` | Background cache (`lib/fcm_cache.asm`) |

Differences from the original
-----------------------------

* **Graphics.**
  * Everything is redrawn in 256 colours. The board uses the combat figures, not separate
    board icons.
  * A piece being moved on the board walks, with its arena walk cycle for the direction
    it is going. The original slid a still icon.
  * The luminance squares go through a grey scale, from the dark squares' near-black to
    the light squares' white. The C64 had to cycle through colours (blue, purple, green,
    cyan).
  * Spells have effects of their own (see Spell effects above).
* **Hits.** Every attack hits when its pixels touch the foe's current frame: missiles,
  swords, the Phoenix's flames (normal or doubled) and the Banshee's ring (`sprite_touch`
  in `src/combat.asm`).
* **Sound.** The music plays on SID 2, at the correct PAL pitch.
* **Options.** F3 names the computer's side directly ("computer plays Light/Dark"). The
  original's F3 meant "the side that moves first / the other side".
* **AI.** Ground paths are checked with a breadth-first search, which allows a few more
  detours than the original.
